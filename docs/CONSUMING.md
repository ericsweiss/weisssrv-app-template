# Generating and updating a tenant repo

This is a [copier](https://copier.readthedocs.io) template. `copier copy`
renders it into a new repository; `copier update` replays the recorded answers
against a newer template tag, so a fix made here reaches every generated repo as
a reviewable diff.

```bash
pipx install 'copier>=9.15.0'           # or: uv tool install 'copier>=9.15.0'
copier copy https://github.com/ericsweiss/weisssrv-app-template.git my-service
cd my-service && git init && git add -A && git commit -m "chore: generate from template"
```

[VERSIONING.md](VERSIONING.md) says why the floor is 9.15.0.

The command uses the public GitHub mirror. The canonical project on
`git.ericsweiss.com` serves the same tags but needs an account on that instance.
Copier records the source URL as `_src_path`, and every later `copier update`
pulls from it.

Answers land in `.copier-answers.yml`. Later:

```bash
copier update                           # re-render at the newest template tag
copier update --data enable_hpa=true    # flip one answer and re-render
```

`copier update` is a three-way merge: your edits survive, the template's changes
arrive, and a genuine conflict lands as conflict markers to resolve. Commit
before running it.

For the design this template encodes, see [ARCHITECTURE.md](ARCHITECTURE.md);
for the pipeline choice, [CI-SHAPES.md](CI-SHAPES.md).

## The answers

**Site identity has no default** — not the app's own names, and not the facts
about the cluster it deploys into. Those questions carry a `placeholder:`
showing the shape and a validator that rejects an empty answer, so a
defaults-only run is refused rather than producing a repo wired to whichever
cluster this template was extracted from. What is defaulted is what composes
from an answer already given (the registry hosts, the node-label prefix) or is
a template-wide choice (the port, the CI shape, the component switches).

A "—" in the Default column below means there is none: the placeholder shown
is an example, not a value you can accept by pressing enter.

### App identity

| Answer | Default | What it drives |
|---|---|---|
| `app_slug` | — | Repository name, Flux Kustomization, every `metadata.name`, the hostname's first label. A DNS label. |
| `app_namespace` | `{{ app_slug }}` | The namespace the operator creates and scopes the Flux service account to. |
| `app_port` | `8080` | The container port, the Service, the IngressRoute backend and both NetworkPolicy ingress rules — one answer, four places. Must be >= 1024: the pod runs as UID 65532 and cannot bind a privileged port. |
| `replica_count` | `2` | Deployment replicas. At 1 no PodDisruptionBudget is generated — `minAvailable: 1` on one replica blocks every voluntary eviction, so a node could never drain. Ignored when `enable_hpa` is on. |
| `copyright_holder` | — | The name on the generated `LICENSE` (MIT), which the generated README links as the repository's own. The year is filled in at render time. This template's licence covers the template, not what it renders, so there is nothing sensible to default to. |

### Cluster identity

| Answer | Default | What it drives |
|---|---|---|
| `external_domain` | — | The public hostname and the external-dns target annotation. |
| `internal_domain` | — | The LAN/tailnet hostname. Must differ from `external_domain` **including its first label** — the two TLS Secrets are named after that label, and a collision puts two Certificates on one Secret. |
| `node_label_domain` | `{{ internal_domain }}` | Node-label prefix (`<prefix>/nas`, `<prefix>/cpu`) for the scheduling affinity and the build's CPU selector. |
| `internal_vip` | — | The address the operator points the internal hostname at. Documentation only; nothing dials it — which is why it is asked further down, with `enable_internal_ingress`, and skipped entirely when that is off. |
| `registry_host` | `registry.git.{{ external_domain }}`, or `ghcr.io` when `forge` is `github` | Registry in the Deployment's `image:`. |
| `registry_pull_host` | `{{ registry_host }}` | A second hostname keyed into the pull credential, for clusters that resolve the registry internally. The image reference always names `registry_host`. Defaults to `registry_host`, the single-name case; answer the internal name only when your nodes resolve or rewrite the registry to a different host. The kubelet matches a pull secret against the literal host in the image reference. When the two names differ, the credential carries both. When they match, it carries one. Asked only when `enable_registry_pull_secret` is on. |
| `runbook_url` | — | The cluster repo's day-two runbooks page (`docs/RUNBOOKS.md` in a cluster generated by weisssrv-cluster-template). On `gitlab` and `github` every generated alert's `runbook_url` is its own section of the generated `docs/RUNBOOKS.md`, and that page links this one for the platform side of each cause. On `other` every alert links this page. A guessed one is a 404 read at 3am. |

### Forge and CI

| Answer | Default | What it drives |
|---|---|---|
| `forge` | derived from `ci_shape` | Where the repo lives: `gitlab`, `github` or `other`. Decides the issue and change-request templates and the word the docs use for a reviewed change — never the pipeline. A repo with no pipeline still lives on a forge. |
| `ci_shape` | `gitlab_selfhosted` | Which pipeline ships — see [CI-SHAPES.md](CI-SHAPES.md). Flux deploys the repo in all three. |
| `change_request` | `pull request` on `github`, `merge request` on `gitlab`, `change request` on `other` | The forge's word for a reviewed change, substituted into every generated doc, agent file and Cursor rule, so the instruction names an object the forge has. Asked only when `forge` is `other`, where `change request` is the prefill. |
| `enable_image_build` | `true` | The placeholder `Dockerfile` and the build job. Off for a service that runs an upstream image. |
| `git_host` | derived from `forge`: `github.com` on GitHub, `git.{{ external_domain }}` otherwise | The forge this repo lives on: the library include host, the AI-review URL, the repo URL in the operator's wiring. |
| `git_namespace` | — | The group/user path that owns the repo. Also the middle segment of the image path. |
| `runbooks_page` | computed, never asked | This repo's `docs/RUNBOOKS.md` as its forge serves the file. Each alert links its own section of it. Empty on `other`, where each alert links `runbook_url`, or `db_runbook_url` for `DatabaseAbsent`. |
| `privileged_runner_tag` | — | Runner tag for the image build, the one job that needs a privileged runner. Asked only for the GitLab shape with a build. Name a privileged runner registered to this repo's group or project, never the cluster's own platform runner: the build runs as root with Docker-in-Docker. With no such runner, turn `enable_image_build` off and build with rootless BuildKit or kaniko on the shared runner in a job of your own. |
| `ci_cpu_selector` | `{{ node_label_domain }}/cpu=modern` | Node selector pinning the CPU-sensitive jobs — secret detection always, the image build when it exists — to a modern CPU. Asked for the whole GitLab shape, because the library defaults it to its own cluster's label domain and a selector no node carries leaves the job Pending. Required, and must match the runner's `node_selector_overwrite_allowed` regex `^[a-z0-9.-]+/cpu=(modern\|legacy)$`: the pipeline always passes the input, and an empty value fails that regex at pod creation rather than skipping the pin. |
| `k8s_version` | `1.37.1` | The Kubernetes minor kubeconform validates against, in the pipeline and `Taskfile.yml`. |

### Secrets

| Answer | Default | What it drives |
|---|---|---|
| `secrets_backend` | `onepassword` | `onepassword`, `gitlab` or `none`. Chooses the ExternalSecret's store and `remoteRef` shape, and whether the Deployment gets a secret `env` block at all. Must match what the operator provisions. |
| `onepassword_vault` | `{{ app_namespace }}` | 1Password only: the tenant's own vault. It must equal `app_namespace`, because the cluster's tenant-wiring gate accepts a tenant store only on the vault named after its namespace. The operator's `ClusterSecretStore` reads it and nothing else, and the tenant's Connect token is scoped to it alone. A store naming a vault that does not exist is accepted by the API server and then fails every fetch. |
| `secret_item` | `App Secrets` | 1Password only: the item title, which renders as the prefixed `"<slug>: <item>"`. |
| `gitlab_api_url` | `https://{{ git_host }}` | GitLab only: the instance holding the CI/CD variables. Separate from `git_host` because the variables need not live on the forge the code does — and because `forge: github` defaults `git_host` to github.com, which is not a GitLab instance. The ESO provider's own default is `https://gitlab.com`, so the store always names it explicitly. |

### Optional components

Each renders a manifest **and** its line in `kustomization.yaml`, so an enabled
component is wired and a disabled one leaves nothing behind. There is no
`optional/` directory and no commented resource list to forget.

| Answer | Default | Renders |
|---|---|---|
| `enable_servicemonitor` | `false` | The ServiceMonitor and the matching scrape NetworkPolicy. **Off by default**: a ServiceMonitor pointed at an endpoint that does not exist yet scrapes `up == 0` and raises TargetDown in the *operator's* Alertmanager. Turn it on with the change that adds `/metrics`. |
| `enable_public_ingress` | `true` | The public IngressRoute **and** its Certificate, together. Off for an app reachable only on the LAN/tailnet, which then needs `enable_internal_ingress`: at least one of the two must be on. |
| `enable_internal_ingress` | `false` | The internal IngressRoute **and** its Certificate, together — one without the other serves from a TLS Secret that never exists. Needs one operator DNS step. |
| `enable_vpa` | `true` | The VerticalPodAutoscaler. Needs the VPA CRD, the recommender and the admission controller that applies its recommendation at pod creation, and a metrics-server. Off for a workload whose requests are hand-tuned. |
| `enable_hpa` | `false` | The HPA; the Deployment then ships no `replicas:` and the VPA, if enabled, becomes memory-only, so the two autoscalers never both drive CPU. |
| `enable_registry_pull_secret` | `{{ enable_image_build and secrets_backend != 'none' }}` | The `dockerconfigjson` ExternalSecret **and** the pod's `imagePullSecrets:` entry. Defaulted on for the combination that needs it — both forges publish privately by default (a GitLab project registry; a GHCR package, whose visibility does not follow the source repo's), so a repo that builds its own image cannot be pulled without it. No `ci_shape` term: the rendered chain is forge-neutral — the ExternalSecret keys on `registry_host`/`registry_pull_host` and reads a username+token pair, which is what `docker login ghcr.io` takes. The backend term is not redundant with the `when:`: a skipped question's default is still evaluated, and `registry_pull_host`'s `when:` reads it with no backend guard, so without it a `secrets_backend: none` repo that builds its own image is asked for a pull host nothing renders. |
| `enable_sso` | `false` | The Authentik forward-auth middleware on the public route. The middleware alone authenticates nothing — the operator's provider/application/outpost objects are what enforce it. The internal hostname stays LAN/tailnet-filtered rather than authenticated. Needs `enable_public_ingress`. |

### Database (1Password backend only)

| Answer | Default | What it drives |
|---|---|---|
| `database` | `none` | `postgres` renders `kubernetes/db/`: a one-instance CloudNativePG `Cluster`, its object store and nightly base backup, three role Secrets, network policies, a PodMonitor, a nightly `pg_dump` and an absence alert, plus the Deployment's file mounts and `/readyz` probe. Needs the cluster's CloudNativePG module and its `tenant-local` StorageClass (ONBOARDING O6b). With `postgres`, `app_port` must not be 5432, 8000 or 9187: the app's allow policies exclude the database pods, which share its name label, by one component label, and a distinct port keeps a database port out of them regardless. |
| `db_name` | the slug with `-` as `_` | The database name: a lowercase identifier, not a YAML keyword such as `true` or `null`, and not a PostgreSQL built-in (`postgres`, `template0`, `template1`), which CNPG cannot create as the application database. |
| `db_role_prefix` | `db_name` | The roles `<prefix>_migrate`, `<prefix>_app` and `<prefix>_ro`. |
| `db_storage_size` | `20Gi` | The instance claim, requested from `tenant-local` and counted by the namespace's storage quota. |
| `db_backup_bucket` | none, required | The bucket holding the WAL archive and base backups. Bucket names are global, so prefix it with the cluster: `<cluster>-cnpg-<slug>`. |
| `db_backup_endpoint` | none, required | The bucket's S3 endpoint, `https://` with no path. A public object store endpoint only (the database egress policy excludes private and cluster addresses): an IP literal or a `.svc`, `.svc.cluster.local`, `.local`, `.internal` or `localhost` host is refused. |
| `db_backup_item` | `CNPG Backup` | The 1Password item (`"<slug>: <item>"`) with `access-key-id` and `secret-access-key`; no double quote, backslash, control character or edge space. |
| `db_roles_item` | `Database` | The 1Password item (`"<slug>: <item>"`) with `migrate-password`, `app-password` and `ro-password`; the same title rules. |
| `db_apiserver_cidrs` | none, required | The API server node `/32`s the instance pods may reach on 6443; each entry a real IPv4 address and `/32`. |
| `db_dump_timezone` | `Etc/UTC` | The time zone of the 02:45 dump schedule. The answer is checked for shape only; the render gate (`tests/validate_render.py`) checks the zone exists in the IANA database. |
| `db_runbook_url` | none, required | The cluster repo's CloudNativePG runbook, which the `DatabaseAbsent` section of the generated `docs/RUNBOOKS.md` links. On `other` the alert links it directly. |

### Library pin (GitLab shape only)

| Answer | Default | What it drives |
|---|---|---|
| `lib_ref` | `v0.23.0` | The tag the generated pipeline declares in its `spec:` header and every `include:` reads. A release tag, never a branch: the generated repo's own `check-lib-pins.py` enforces the shape on the first pipeline. |
| `lib_project` | `eric/weisssrv-lib` | The library's project path. `include: project:` resolves instance-locally, so the library must live on the same GitLab as the repo. |

## What your cluster must provide

The manifests name platform objects directly. A cluster generated by
weisssrv-cluster-template satisfies all of it; another cluster needs these
before the first reconcile succeeds.

- **CRDs**: `traefik.io` IngressRoute and Middleware, `cert-manager.io`
  Certificate and ClusterIssuer, `monitoring.coreos.com` ServiceMonitor and
  PrometheusRule, `autoscaling.k8s.io` VerticalPodAutoscaler unless
  `enable_vpa` is off, and
  `external-secrets.io` ExternalSecret and ClusterSecretStore unless
  `secrets_backend` is `none`.
- **Named objects**: a Traefik `websecure` entryPoint; the Middlewares
  `hsts-header` and `lan-tailscale-only` in namespace `traefik` and
  `authentik-auth` in namespace `authentik`; a ClusterIssuer named
  `letsencrypt-prod`, whose DNS-01 solver must also hold credentials for
  `internal_domain` — the internal name is validated over public DNS even
  though it resolves only on the LAN.
- **Traefik** with `providers.kubernetesCRD.allowCrossNamespace: true`, or the
  route cannot reference a middleware in another namespace.
- **Prometheus** with `ruleSelectorNilUsesHelmValues: false` and
  `serviceMonitorSelectorNilUsesHelmValues: false`, so rules and ServiceMonitors
  are discovered without a release label. Left true, the operator's selector is
  `matchLabels: {release: <release>}`, which these objects do not carry, and the
  down alert never fires.
- **A cluster-scoped `tenant-crd-editor` ClusterRole** granting edit on
  `traefik.io`, `monitoring.coreos.com`, `autoscaling.k8s.io`,
  `external-secrets.io` and `cert-manager.io`. The operator's wiring file binds
  it. `admin` does not aggregate those groups, and a RoleBinding to a missing
  ClusterRole applies cleanly and grants nothing.
- **Namespaces** `traefik`, `observability` and `kube-system`, the peers the
  NetworkPolicies name, plus `authentik` for the middleware above when
  `enable_sso` is on. The DNS rule ANDs `kube-system` with the pod label
  `k8s-app: kube-dns`, so on a cluster whose CoreDNS pods carry another label the
  peer matches nothing and the app resolves no names.
- **kube-state-metrics**, scraped by that Prometheus. `AppDown` and `AppAbsent`
  read `kube_deployment_status_replicas_available`; without it AppAbsent fires
  permanently and AppDown never fires.
- **cert-manager controller metrics**, scraped by that Prometheus. The rendered
  repo declares no certificate alert of its own, because the platform already
  alerts cluster-wide on expiry and on a Certificate that never goes Ready.
  Without those metrics a Certificate that stops renewing is invisible.
- **For `database: postgres`** (the `kubernetes/db` tree):
  - the CloudNativePG operator and Barman Cloud plugin, with the
    `postgresql.cnpg.io` and `barmancloud.cnpg.io` CRDs, which
    `tenant-crd-editor` must also grant;
  - the `monitoring.coreos.com` `PodMonitor` CRD, and Prometheus with
    `podMonitorSelectorNilUsesHelmValues: false`. Left true, the PodMonitor is
    never discovered, `cnpg_collector_up` is never scraped, and
    `DatabaseAbsent` pages for ever on a healthy database;
  - the operator in namespace `cnpg-system`, its pods labelled
    `app.kubernetes.io/name: cloudnative-pg`, which the instance ingress policy
    admits on port 8000;
  - a `tenant-local` StorageClass for the instance claim.
- **A resource-metrics API** (metrics-server) when `enable_hpa` or `enable_vpa`
  is on, plus the VPA recommender and admission controller for `enable_vpa`.
  Without them the VPA recommends nothing and the HPA never leaves
  `minReplicas`, with no alert.
- **A 1Password Connect Service** named `onepassword-connect` in namespace
  `external-secrets` on port 8080, when `secrets_backend` is `onepassword`. Its
  Connect server must be granted each tenant's own vault. A store naming a vault
  the server cannot read fails every fetch.
- **external-dns** watching the `traefik-proxy` source with the alpha
  annotation prefix, for the public hostname's record. The public route targets
  the zone apex, so the apex itself must resolve to the cluster's public
  ingress. A cluster whose edge is a different name retargets the annotation in
  `kubernetes/flux/ingressroute.yaml`.
- **Node labels** under `node_label_domain` (`<prefix>/nas`, `<prefix>/cpu`).
- **A Flux Kustomization named `infrastructure-configs`** in `flux-system`, or
  another name for the stage that applies the platform CRDs. The wiring file's
  `dependsOn` names it, and a name the cluster does not have leaves the tenant
  Kustomization retrying forever with nothing applied.
- **The `tenant-traefik-hostnames` and `tenant-certificates`
  ValidatingAdmissionPolicies.** The wiring file binds both to the tenant
  namespace, with a `tenant-routing-<namespace>` ConfigMap in `flux-system` as
  their parameter. A binding to a missing policy admits everything, with no
  error.
- **A `cluster-config` ConfigMap** in `flux-system`. Every tenant Kustomization
  in the wiring file names it under `postBuild.substituteFrom`, and a missing
  one fails the reconcile.

## What the generated repo contains

```
kubernetes/flux/     # everything Flux reconciles into the namespace
docs/                # ONBOARDING (the operator's wiring, rendered), ARCHITECTURE, VERSIONING, RUNBOOKS
scripts/             # library helpers plus this template's own gates — see below
Taskfile.yml         # the local gates and read-only cluster checks
.copier-answers.yml  # the answers, replayed by `copier update`
```

Plus the pipeline for the chosen shape, a placeholder `Dockerfile` and its build
job when `enable_image_build` is on (on the GitHub shape that job is the whole
`build-image.yml` workflow, dropped with the answer so a repo running an
upstream image gets no `packages: write` workflow), and the agent files
(`CLAUDE.md`, `AGENTS.md`, the `project-development` skill, Cursor rules).

## Changing the generated repo by hand

Nothing stops you — it is your repository. Three things to know:

- **Adding a manifest** means adding its line to
  `kubernetes/flux/kustomization.yaml`. A file Flux never builds is inert, and
  inert manifests rot.
- **`copier update` re-renders the files it generated.** An edit inside one of
  them is preserved by the three-way merge, but a change you would rather keep
  forever is better made as an answer here, or upstream in this template.
- **The vendored files are the exception.** These are byte-identical library
  copies: the helpers under `scripts/` named below, `.gitattributes`,
  `examples/netpol-except.example.yaml`, and on the GitHub shape
  `.github/workflows/ci.yml`, `release.yml` and `build-image.yml`. A generated
  repo carries no gate that notices an edit to one. A re-vendor overwrites it,
  and `copier update` quietly carries it forward as a fork nothing records.
  Change them upstream.

## The vendored library helpers

Every helper script under `template/scripts/` is a **byte-identical copy** of a
[`eric/weisssrv-lib`](https://git.ericsweiss.com/eric/weisssrv-lib) file, so the
copy is what executes. On the GitLab shape, `lib-ref-sites.yml` beside them
is site data, not a copy. Some are run by the library's job templates from those
paths. The three manifest gates are run by the generated repo's pipeline and by
`task lint`, and `flux-lint.sh` by both at once — the `flux-lint` include runs
the repo's own copy. `check-netpol-except-parity.py` imports `gate_common.py`,
and `check-lib-pins.py` and `check-ci-include-job-names.py` both import
`ci_yaml.py`, each from its own directory, so those sets ship together.

Every generated repo carries `check-comment-length.py`, `check-doc-links.py`,
`check-netpol-except-parity.py` with `gate_common.py`, `check-scrape-wiring.py`,
`check-kustomization.py` and `flux-lint.sh`. The rest depend on the answers —

| Answer | What else ships |
|---|---|
| `ci_shape: gitlab_selfhosted` | `check-lib-pins.py` and `check-ci-include-job-names.py` with `ci_yaml.py`, and `semantic-release.py` |
| `ci_shape: github` | `semantic-release.py`; the pin gate has no includes to gate |
| `ci_shape: none` | nothing further; `task lint` and the pre-commit hooks are the whole gate |
| `database: postgres` with the 1Password backend | `check-cnpg-clusters.py` and `check-pvc-storageclass.py`, plus `ci-fetch-tools.py` on the GitLab shape |

This repository owns the copy relationship in `scripts/vendored-manifest.yml`
and the library's `check-vendored-copies.py` gates it — fix a bug upstream and
re-vendor, never in the copy, which the next re-vendor reverts.

The lint profiles are **forks** of library files rather than copies: the same
rules with per-repo paths. They come in two sets, registered separately because
they drift separately —

- at the root, what this template lints **itself** with: `ruff.toml`,
  `.gitleaks.toml`, `lint/yamllint-relaxed.yml`, `.editorconfig`,
  `.pre-commit-config.yaml` and `.gitlab/secret-detection-ruleset.toml`;
- under `template/`, what a generated repo gets: `template/ruff.toml`,
  `template/.gitleaks.toml`, `template/lint/yamllint-relaxed.yml`,
  `template/.editorconfig`, `template/.pre-commit-config.yaml.jinja` and the
  rendered `.gitlab/secret-detection-ruleset.toml`.

The registry records each as a fork and pins the library-side blob it was last
reconciled against, so an upstream change is surfaced rather than silently
ignored.
